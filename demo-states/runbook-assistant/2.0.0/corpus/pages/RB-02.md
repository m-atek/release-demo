Owner: Pieter. Follow every step, in order, for every release. Don't skip steps.

## Steps

1. Merge the release branch into main and write down the commit.
2. Update VERSION and the changelog.
3. Run the full test suite on your laptop. Paste the result into the Jira ticket.
4. Build the package and copy it to the release share, \\files\releases\orders-service.
5. Deploy to staging with the commands in the runbook.
6. Open the staging page and check the version number.
7. Click through the smoke tests: order page, order history, checkout.
8. Fill in the change form and email it to the change manager. Wait for approval at Thursday's change meeting.
9. Ask Pieter to deploy. Only he has production access.
10. Pieter copies the package from the release share to production.
11. Check that the production page shows the new version.
12. If anything looks wrong, ask Pieter to put the previous package back.
13. Update the Jira ticket and the change form with the result.
14. Post in #releases that the release is done.

## Rolling back

If production breaks after a release, ask Pieter to put the previous package back from the release share, then update the change form.
