Every release starts in #releases, from the person who wants it out. Nobody deploys by hand and nobody needs production access to release.

## Start a release

Type `/release <service> <Jira key>`, for example `/release orders-service ORD-12`. Add `standard` for a routine release that a pre-approved standard change covers. The Release Bot answers within three seconds and posts one status message that the pipeline rewrites at every stage.

## What happens next

Jenkins builds the head of main as the user release-bot, with you as the requester. The pipeline runs the tests, the quality gate, the SBOM and scan, publishes the package to JFrog Container Registry, deploys it to staging and checks it, and opens the ServiceNow change. After Change approvers approve, it deploys the same package to production, checks it, and records the result in ServiceNow, Jira, GitHub and Grafana. Slack ends with "Live in" and the real total time.

## Who may start one

Only the people in the Slack handler's releasers list. Anyone else gets a private reply: "You can't start releases here." If the tools host is stopped, Slack says so in one line.
