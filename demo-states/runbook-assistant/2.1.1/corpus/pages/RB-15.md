No cloud key is stored anywhere: not in Jenkins, not in a file, not in SSM.

## How a release reaches the clouds

Jenkins signs an ID token for each build, and AWS, Azure and Google Cloud each trust Jenkins as an identity provider. quote-service's deploy exchanges the build's token for short-lived access in each cloud; the Staging stage's log shows each cloud accepting it and when that access expires.

## On the tools host

The tools host's own AWS access is its instance role, which can assume one deploy role per service. Each deploy role can change only that service's resources.
