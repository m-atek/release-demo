Each environment of orders-service gets only the settings services.yaml gives it.

## The delivery estimate

Staging reads the delivery estimate from DELIVERY_ESTIMATE_DAYS. Production still carries it under its old name, DELIVERY_DAYS. Code that reads only the new name passes staging and fails production's check, which is how 1.4.1 was rolled back to 1.4.0.

## Changing a setting

Change it in services.yaml and release: a setting is part of the release, with a change, not an edit on the function.
